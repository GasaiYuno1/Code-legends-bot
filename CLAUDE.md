# locm-bot — контекст проекта для Claude Code

Бот для CodinGame **Legends of Code & Magic (классическая версия с драфтом)**.
Роли: Андрей — менеджер (ставит задачи, принимает решения), Claude — разработчик.
Отвечать по-русски, на «ты», компактно. Перед крупным шагом — коротко объяснить план.

## Принятые решения
- Язык **C#** (.NET 8, LangVersion 10 — без новых фич, чтобы точно собиралось на CodinGame). Порт ядра на C++ — только если упрёмся в 100 мс.
- Бой: **симулятор правил + полный перебор своего хода** с отсечениями и эвристической оценкой (без стадии «эвристический бот»).
- Драфт: статический рейтинг карт + поправка на мана-кривую; позже статистика из self-play.
- Правила брать из кода официального арбитра: https://github.com/CodinGame/LegendsOfCodeAndMagic (Java, классы `engine/GameState.java`, `Gamer.java`). Симулятор — построчная копия этой логики; при сомнениях смотреть Java, а не конспект. Конспект правил и варианты: `docs/01-rules-and-options.md`.

## Структура
- `src/LocmBot/` — бот. Блочные `namespace Locm { }`, все `using` в начале файла (этого требует склейка). Внешних пакетов нет.
  - `Game/` — модель ввода: `Abilities` (flags), `Card` (readonly struct — карта как в строке ввода), `TurnInput`, `InputParser`, `CardDb` (все 160 карт; **генерируется** `tools/gen_carddb.py`, руками не править).
  - `Sim/` — симулятор правил (этап 1): `GameAction` (SUMMON/ATTACK/USE/PASS, парсинг и формат арбитра), `Creature` (существо на столе), `PlayerState` (здоровье, мана, руны, добор, рука/стол), `GameState` (`FromInput`, `LegalActions`/`IsLegal`, `Apply`/`TryApply`/`ApplySequence`, `EndTurn`, `ToInputLines`, `Clone`/`CopyFrom`). Рука противника и колоды — только счётчики (`HandCount` против известных `HandKnown`); `Players[0]` — я, `Current` — чей ход.
  - `Draft/` — `CardRating` (рейтинг карты: по умолчанию таблица `CardTable` из пиков Legend-игроков арены, `UseTable=false` — формула D1: статы, способности, эффекты минус «норма» для стоимости), `CardTable.cs` (**генерируется** `tools/arena/stats.py`, Брэдли–Терри по предложенным тройкам; упакована в строку ради лимита размера склейки), `RatingDraft` (рейтинг + слабая поправка на мана-кривую: недобор корзины относительно прогресса драфта `TargetCurve·k/30`, `CurveW=0.1`; лимит предметов 8; штраф за 3-ю копию выключен — Legend их не избегает); `FirstCardDraft` — заглушка. Совпадение драфта с пиками Legend (88k пиков, режим `draftcheck`): 86.4%; любая сильная поправка на кривую его снижает. **Поправка из self-play** (`CardTable.SelfPlay`, вес `CardRating.SelfW=20`, ключ `selfw`): `tools/arena/selfplay_cards.py` — 20k партий с ε=0.25 случайных пиков (`draftexplore`), логит-регрессия «победа ~ число копий карты + сторона» по 40k колодам (`data/arena/selfplay_cards.tsv`); корреляция с таблицей пиков 0.81, вниз уходят зелья лечения и мелкие life steal; self-play против чистой таблицы 53.2/53.4/53.5% при весе 10/20/40 (по 2000 партий), совпадение с пиками Legend 89.1% → 85.6%.
  - `Battle/` — `Evaluator` (линейная оценка: стол с бонусами за способности, HP нелинейно, карты в руке, штраф за пробитые руны), `SearchBattle` — два этапа: (1) DFS по последовательностям действий своего хода со статической оценкой — фазы призывы→предметы→атаки, призыв после атак только в освободившийся слот, дедупликация по `GameState.Hash()`, дети по убыванию оценки, 60% бюджета; все посещённые узлы — кандидаты, хранятся `MaxCandidates` лучших (min-heap); (2) кандидаты переоцениваются жадным ответом противника `ReplyScore` (его `EndTurn`, проверка летала «сумма атак − защита моих Guard ≥ HP», затем каждое его существо по убыванию атаки бьёт лучшую для себя цель; карты его руки не учитываются), итог = `ReplyWeight`·ответ + остальное статика; (3) `DeepReplyCandidates` (32) лучших по жадной оценке переоцениваются `DeepReplyScore` — полный перебор последовательностей его атак с дедупликацией и лимитом `DeepReplyNodes` (400): совпадение с ходами Legend 52.8% → 54.0%, self-play против жадного ответа 19:11. (3а, выключено `SampledCandidates=0`) expectimax по сэмплированной руке противника: `OpponentModel` (тройки драфта общие для обоих игроков → его колода = по одной карте из каждой тройки; показанные SUMMON/USE приписываются тройкам паросочетанием, пики остальных сэмплируются softmax'ом рейтинга `CardTable` с температурой 0.5, откалиброванной по 71k пикам; счётчик неизвестных карт сходится с вводом на 4194 ходах арены без расхождений), `SampledReplyScore` — полный ход противника (призывы→предметы→атаки, `FullDfs` с лимитом узлов, дети по оценке) на каждом образце руки, лист — моя оценка. `PassBattle` — заглушка. `IBattleStrategy.WarmUp` — прогрев JIT на первом ходу драфта (≤ `WarmUpMs`=400 мс; `warmup=0` для быстрых локальных матчей), `ObserveDraft` — тройки драфта для модели противника. `Program.cs` принимает `key=value` для локального тюнинга весов (hp, lowhp, def, reply, cand, sampled, hands, samplednodes, warmup, exactlethal, risk, riskw, …).
  - `Bot.cs` — оркестратор (фаза по счётчику ходов + `LooksLikeDraft`, прогрев на ходу 0); необязательный `dump` пишет ввод и ответ каждого хода в формате логов сверки (включается константой `DumpInput` в `Program.cs`). `TurnClock.cs` — тайминг.
- `tests/LocmBot.Tests/` — тесты **без NuGet** (свой мини-раннер `MiniTest.cs`, атрибут `[Test]` на `public static void`). `SimTests` — граничные случаи правил; `Replay.cs` — сверка симулятора с логами арбитра; `tests/fixtures/*.log` — логи случайных партий, сыгранных настоящим движком арбитра (тест `FixturesMatchReferee` требует 0 расхождений и ≥ 200 ходов).
- `tools/bundle.py` — склейка в один файл `dist/codingame.cs` для вставки на CodinGame. `tools/gen_carddb.py` — генерация `CardDb.cs`. `tools/refcheck/` — Java-обвязка над классами движка арбитра (без SDK, со стабами): `run.sh` — случайные партии с подмешанными нелегальными действиями → логи для `replay`; `match.sh` — мини-арбитр «бот против бота/random» (процессы по протоколу CodinGame, стороны чередуются, замер времени хода, подсчёт нелегальных действий и таймаутов, логи в том же формате).
- `tools/arena/` — данные арены CodinGame (нужен доступ к `www.codingame.com` в сетевой политике окружения): `fetch.py` — внутренний API (таблица лидеров → последние бои агентов → реплеи), из реплея берутся сиды арбитра (`refereeInput`), пики обоих игроков и действия по ходам (`summary` кадров) → `data/arena/games.txt`; `replay.sh` + `tools/refcheck/ArenaReplay.java` — воспроизведение партий движком арбитра по сидам (логи в формате replay в `build/arena-logs/`, таблица драфта с предложенными тройками `build/arena-draft.tsv`); `stats.py` — статистика пиков/винрейтов (`data/arena/card_stats.tsv`) и генерация `CardTable.cs`.
- `referee/cardlist.txt` — все 160 карт (формат `baseId ; name ; type ; cost ; atk ; def ; abilities ; myHp ; oppHp ; draw ; text`), совпадает с арбитром.
- `nuget.config` очищает источники пакетов (проект должен собираться без сети). Внешние пакеты не добавлять.

## Ключевые факты правил (см. docs для полного)
- 30 HP, рука ≤ 8, стол ≤ 6, мана ≤ 12; 2-й игрок: 5 стартовых карт, `maxMana` с 1 (на первом ходу 2 маны) и +1 к максимуму, пока впервые не потратит всю ману.
- Способности B/C/D/G/L/W; предметы: зелёный — свои существа, красный — чужие, синий — чужие или лицо (-1). Синий в лицо бьёт полем `defense` (+ `oppHealthChange`). Порядок предмета: ключевые слова → attack (не ниже 0) → defense; Ward поглощает урон предмета целиком.
- Руны 25/20/15/10/5: пробитие руны = +1 добор противнику (лечение руны не возвращает). Добор из пустой колоды или с 50-го хода игрока: за **каждую** недобранную карту минус руна, HP = её значение, без бонусного добора; проверка колоды идёт раньше проверки полной руки.
- Время: 1000 мс на первый ход драфта и первый ход боя, 100 мс на остальные. Ответ — одна строка, действия через `;`. Нелегальные действия — только warning; `PASS` внутри строки просто пропускается; синтаксически кривое действие (в т.ч. двойной пробел) = поражение.
- Ввод: 2 строки игроков (`hp mana deck rune draw`), `oppHand oppActions`, строки действий противника, `cardCount`, карты (`number instanceId location type cost atk def abilities myHp oppHp draw`). `mana` = maxMana; `draw` у меня — сколько добрал в этот ход, у противника — сколько доберёт в следующий. instanceId нечётные у первого игрока, чётные у второго (`GameState.IsSecondPlayer`).
- Причуда арбитра: у существа на столе поля myHp/oppHp/draw во вводе обнуляются после первого боя или предмета; зелёный предмет «не убивает» (существо остаётся как было).

## План этапов
0. ✅ Каркас: парсер, модель, заглушки, тесты, склейка.
1. ✅ Симулятор правил (`GameState`, применение действий, генерация легальных ходов) + тесты граничных случаев; сверка с движком арбитра: 62 случайные партии (~4000 ходов) и **1474 реальные партии Legend с арены (35 781 ход)** — 0 расхождений. В репозитории фикстуры: 24 случайных лога + 4 лога арены.
2. ✅ Драфт по рейтингу + мана-кривая; бой — полный перебор своего хода с простой оценкой. Локально: против random 10:0, self-play без таймаутов (полный перебор укладывается в ~35 мс, бюджет 85 мс), 0 нелегальных действий. На арене: Silver (формульный драфт, без модели ответа); с таблицей Legend и моделью ответа — Legend, 37-е место из 167 (56% побед по 230 партиям); со слабой кривой и глубоким ответом — 20-е место (66% по 174 партиям; худшие соперники LH 1:6, Coac 1:4, dbdr 3:6); с SPSA-весами и поправкой драфта из self-play — **1-е место** (см. этап 3).
3. Модель ответа противника ✅ (жадные атаки; self-play против версии без неё 19:11). Рейтинг драфта по пикам Legend ✅ (`CardTable`, 71 010 пиков из 1474 партий; self-play против формульного драфта 25:5). Сравнение с реальными ходами Legend (`compare`, 4000 ходов): совпадение 52.8%, поиск не пропускает ходы (0.1%), расхождения — в оценке (31%); веса hp/def/hand/reply дают ±0.5% (шум); с глубоким ответом `hp=0.3` даёт 55.4%, но арена (A/B: 174 партии на 0.1 → 65.5%, 17-е место; 220 партий на 0.3 → 59.1%, 20-е) говорит обратное — **оставлен 0.1; совпадение с Legend и self-play не заменяют арену, каждое изменение проверять на ≥ 200 партиях арены**, штрафы за защиту 1–2 (`fragile1/2`) и бонус синим в руке (`blue`) снижают совпадение — выключены (веса оставлены для опытов). Обучение весов логистической регрессией на исходах партий (`tools/arena/learn_eval.py`, 15.8k позиций, точность 69%) даёт Ward/Lethal ×3, руку 2.3, но совпадение с ходами падает до 51.5%, self-play нейтрален — не принято; по весам оценка исчерпана, дальше только структурные изменения. Третий полуход (`CounterCandidates`: мой следующий ход после ответа противника, статика на листьях): совпадение 55.4% → 47.4%, до 94 мс — выключен (эффект горизонта); если возвращаться — только с ответом противника и на мой следующий ход. Отдельная оценка для модели противника (`SearchBattle.OppEval`, ключи `o_*`, режим `replycheck`: предсказанные атаки против реальных ответов Legend, база 46% целиком / 54% по существам): `o_oppdraw=0.5` предсказывает лучше (48.7/56.4%), но совпадение моих ходов 55.0% и self-play 8:22 — не принято; остальные `o_*` веса ничего не меняют. Расширение глубокой переоценки (deep=64, nodes=800) — без изменений. Против топ-1 (Shand, 334 логов) совпадение всего 32.7%: он строит стенки-Guard и не разменивает существ ради урона в лицо; при этом мой поиск находит леталы через баффы предметами, которые он пропускает (64 против 51 на 1500 ходов, проверено `dumplethal`). Вес HP в зоне 10–20 (`midhp`), `mydraw=0.6`, `hand=1.5` — шум (compare −0.3…−1.3%, self-play 31:29 на 60 партиях). `selfplay_tune.py` с порогом 60% на 40 партиях принимает шум — для решений нужны ≥ 80 партий. `bench`: 395 узлов/мс, тяжёлые позиции перебираются целиком. **Обучаемая оценка на листьях** (`Battle/NetEval.cs`: 49 признаков `NetFeatures`, сеть 49→32→1, веса `NetWeights.cs` от `tools/arena/train_net.py` по выгрузке режима `features`; включается `net=1`, `netadd=1` — как поправка к линейной): на holdout предсказывает исход на 72.6% (логистика 71.6%), но в бою хуже линейной — self-play 30:50 (замена), 15:25 и 21:19 (поправка ×2 и ×5), совпадение с Legend 37%, до 92 мс. Вывод: «предсказание исхода» ≠ «ценность листа»; если возвращаться — учить на цели, согласованной с поиском (например, TD/self-play), а не на исходах. `selfplay_tune.py` итог: 41/80 против эталона — набор {hand 1.5, hp 0.45, guard 1.2, oppdraw 2.5} не принят. Примеры расхождений: Legend-боты дороже ценят карты в руке (не тратят removal ради мелкой выгоды) и добор. ## Следующий шаг: партии с арены CodinGame (данные сильных ботов вместо self-play)
Нужен доступ к `www.codingame.com` (сетевая политика окружения: Network access = Custom, домены `www.codingame.com` и `*.codingame.com`; действует только для новых сессий). Затем `tools/arena/`: скрапер на Python без зависимостей.
Внутренний API (по чужим скраперам, проверить при первом запуске; все запросы — POST с JSON-массивом в теле):
- `https://www.codingame.com/services/Leaderboards/getFilteredPuzzleLeaderboard` тело `["legends-of-code-and-magic", null, "global", {"active": false, "column": "", "filter": ""}]` → игроки с `agentId` и лигой;
- `https://www.codingame.com/services/gamesPlayersRanking/findLastBattlesByAgentId` тело `[agentId, null]` → последние бои (`gameId`, игроки);
- `https://www.codingame.com/services/gameResult/findByGameId` тело `[gameId, null]` → кадры: `gameInformation` (тексты арбитра: «Player X chose …» на драфте, «performed action: …» в бою, «[Warning] … not legal»), `view` (данные просмотрщика с картами).
Цели: (1) таблица по картам — частота пика и винрейт колод с картой по лигам → рейтинг драфта D3 вместо формулы; (2) сравнение реальных ходов противников с `SearchBattle.ReplyScore`; (3) логи для `replay`.
