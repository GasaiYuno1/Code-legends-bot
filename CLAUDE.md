# locm-bot — контекст проекта для Claude Code

Бот для CodinGame **Legends of Code & Magic (классическая версия с драфтом)**.
Роли: Андрей — менеджер (ставит задачи, принимает решения), Claude — разработчик.
Отвечать по-русски, на «ты», компактно. Перед крупным шагом — коротко объяснить план.

## Принятые решения
- Язык **C#** (.NET 8, LangVersion 10 — без новых фич, чтобы точно собиралось на CodinGame). Порт ядра на C++ — только если упрёмся в 100 мс.
- Бой: **симулятор правил + полный перебор своего хода** с отсечениями и эвристической оценкой (без стадии «эвристический бот»).
- Драфт: статический рейтинг карт + поправка на мана-кривую; позже статистика из self-play.
- Правила брать из кода официального арбитра: https://github.com/CodinGame/LegendsOfCodeAndMagic (Java, классы `engine/GameState.java`, `Gamer.java`). Симулятор — построчная копия этой логики; при сомнениях смотреть Java, а не конспект. Конспект правил и варианты: `docs/01-rules-and-options.md`.

## Структура
- `src/LocmBot/` — бот. Блочные `namespace Locm { }`, все `using` в начале файла (этого требует склейка). Внешних пакетов нет.
  - `Game/` — модель ввода: `Abilities` (flags), `Card` (readonly struct — карта как в строке ввода), `TurnInput`, `InputParser`, `CardDb` (все 160 карт; **генерируется** `tools/gen_carddb.py`, руками не править).
  - `Sim/` — симулятор правил (этап 1): `GameAction` (SUMMON/ATTACK/USE/PASS, парсинг и формат арбитра), `Creature` (существо на столе), `PlayerState` (здоровье, мана, руны, добор, рука/стол), `GameState` (`FromInput`, `LegalActions`/`IsLegal`, `Apply`/`TryApply`/`ApplySequence`, `EndTurn`, `ToInputLines`, `Clone`/`CopyFrom`). Рука противника и колоды — только счётчики (`HandCount` против известных `HandKnown`); `Players[0]` — я, `Current` — чей ход.
  - `Draft/` — `CardRating` (рейтинг карты: по умолчанию таблица `CardTable` из пиков Legend-игроков арены, `UseTable=false` — формула D1: статы, способности, эффекты минус «норма» для стоимости), `CardTable.cs` (**генерируется** `tools/arena/stats.py`, Брэдли–Терри по предложенным тройкам; упакована в строку ради лимита размера склейки), `RatingDraft` (рейтинг + слабая поправка на мана-кривую: недобор корзины относительно прогресса драфта `TargetCurve·k/30`, `CurveW=0.1`; лимит предметов 8; штраф за 3-ю копию выключен — Legend их не избегает); `FirstCardDraft` — заглушка. Совпадение драфта с пиками Legend (88k пиков, режим `draftcheck`): 86.4%; любая сильная поправка на кривую его снижает.
  - `Battle/` — `Evaluator` (линейная оценка: стол с бонусами за способности, HP нелинейно, карты в руке, штраф за пробитые руны), `SearchBattle` — два этапа: (1) DFS по последовательностям действий своего хода со статической оценкой — фазы призывы→предметы→атаки, призыв после атак только в освободившийся слот, дедупликация по `GameState.Hash()`, дети по убыванию оценки, 60% бюджета; все посещённые узлы — кандидаты, хранятся `MaxCandidates` лучших (min-heap); (2) кандидаты переоцениваются жадным ответом противника `ReplyScore` (его `EndTurn`, проверка летала «сумма атак − защита моих Guard ≥ HP», затем каждое его существо по убыванию атаки бьёт лучшую для себя цель; карты его руки не учитываются), итог = `ReplyWeight`·ответ + остальное статика; (3) `DeepReplyCandidates` (32) лучших по жадной оценке переоцениваются `DeepReplyScore` — полный перебор последовательностей его атак с дедупликацией и лимитом `DeepReplyNodes` (400): совпадение с ходами Legend 52.8% → 54.0%, self-play против жадного ответа 19:11. `PassBattle` — заглушка. `IBattleStrategy.WarmUp` — прогрев JIT на первом ходу драфта (≤ 400 мс). `Program.cs` принимает `key=value` для локального тюнинга весов (hp, lowhp, def, reply, cand, …).
  - `Bot.cs` — оркестратор (фаза по счётчику ходов + `LooksLikeDraft`, прогрев на ходу 0); необязательный `dump` пишет ввод и ответ каждого хода в формате логов сверки (включается константой `DumpInput` в `Program.cs`). `TurnClock.cs` — тайминг.
- `tests/LocmBot.Tests/` — тесты **без NuGet** (свой мини-раннер `MiniTest.cs`, атрибут `[Test]` на `public static void`). `SimTests` — граничные случаи правил; `Replay.cs` — сверка симулятора с логами арбитра; `tests/fixtures/*.log` — логи случайных партий, сыгранных настоящим движком арбитра (тест `FixturesMatchReferee` требует 0 расхождений и ≥ 200 ходов).
- `tools/bundle.py` — склейка в один файл `dist/codingame.cs` для вставки на CodinGame. `tools/gen_carddb.py` — генерация `CardDb.cs`. `tools/refcheck/` — Java-обвязка над классами движка арбитра (без SDK, со стабами): `run.sh` — случайные партии с подмешанными нелегальными действиями → логи для `replay`; `match.sh` — мини-арбитр «бот против бота/random» (процессы по протоколу CodinGame, стороны чередуются, замер времени хода, подсчёт нелегальных действий и таймаутов, логи в том же формате).
- `tools/arena/` — данные арены CodinGame (нужен доступ к `www.codingame.com` в сетевой политике окружения): `fetch.py` — внутренний API (таблица лидеров → последние бои агентов → реплеи), из реплея берутся сиды арбитра (`refereeInput`), пики обоих игроков и действия по ходам (`summary` кадров) → `data/arena/games.txt`; `replay.sh` + `tools/refcheck/ArenaReplay.java` — воспроизведение партий движком арбитра по сидам (логи в формате replay в `build/arena-logs/`, таблица драфта с предложенными тройками `build/arena-draft.tsv`); `stats.py` — статистика пиков/винрейтов (`data/arena/card_stats.tsv`) и генерация `CardTable.cs`.
- `referee/cardlist.txt` — все 160 карт (формат `baseId ; name ; type ; cost ; atk ; def ; abilities ; myHp ; oppHp ; draw ; text`), совпадает с арбитром.
- `nuget.config` очищает источники пакетов (проект должен собираться без сети). Внешние пакеты не добавлять.

## Команды
```
dotnet build src/LocmBot -c Release
dotnet run --project tests/LocmBot.Tests                                  # все тесты; аргумент = фильтр по имени
dotnet run --project tests/LocmBot.Tests -- replay <файлы|каталог>       # сверка симулятора с логами арбитра
dotnet run --project tests/LocmBot.Tests -- compare <логи> [мс] [limit=N] [step=K] [dump=N] [key=value]  # мой поиск против реальных ходов из логов
dotnet run --project tests/LocmBot.Tests -- draftcheck <логи> [-v] [key=value]                        # мой драфт против реальных пиков
dotnet run --project tests/LocmBot.Tests -- replycheck <логи> [limit=N] [step=K] [o_key=value]         # модель ответа против реальных ответов противников
tools/refcheck/run.sh <клон LegendsOfCodeAndMagic> [seed] [игр] [каталог] # новые логи движком арбитра (Java 17+)
tools/refcheck/match.sh <клон> <игр> <seed> "<cmd A>" "<cmd B>" [логи]  # матчи; cmd = "dotnet src/LocmBot/bin/Release/net8.0/LocmBot.dll" или random
python3 tools/gen_carddb.py                                              # referee/cardlist.txt -> Game/CardDb.cs
python3 tools/bundle.py                                                  # -> dist/codingame.cs (без комментариев, чистый ASCII; файл в git — пересобирать перед пушем)
python3 tools/paste_page.py                                              # -> build/paste.html: страница «скопировать код» для телефона (публикуется как артефакт)
python3 tools/arena/fetch.py --league 6 --agents 30 --max-games 1500     # партии арены -> data/arena/games.txt (дописывает новые)
python3 tools/arena/fetch.py --handle <handle из URL профиля> --out build/user/games.txt   # бои одного игрока (свои: 712b3621df6ce65a3eff2bd78ab18e752899972)
tools/arena/replay.sh <клон>                                             # воспроизведение движком -> build/arena-logs, build/arena-draft.tsv
python3 tools/arena/stats.py                                             # -> data/arena/card_stats.tsv, src/LocmBot/Draft/CardTable.cs
python3 tools/arena/learn_eval.py build/arena-logs                       # веса оценки регрессией на исходах (эксперимент, печатает key=value для compare)
python3 tools/arena/tune.py build/arena-logs                             # покоординатный подбор весов по совпадению с ходами Legend
```
Формат лога сверки: блоки «ввод арбитра как есть» + строка `> ответ бота`; строки с `#` и пустые игнорируются; ходы драфта пропускаются.

## Ключевые факты правил (см. docs для полного)
- 30 HP, рука ≤ 8, стол ≤ 6, мана ≤ 12; 2-й игрок: 5 стартовых карт, `maxMana` с 1 (на первом ходу 2 маны) и +1 к максимуму, пока впервые не потратит всю ману.
- Способности B/C/D/G/L/W; предметы: зелёный — свои существа, красный — чужие, синий — чужие или лицо (-1). Синий в лицо бьёт полем `defense` (+ `oppHealthChange`). Порядок предмета: ключевые слова → attack (не ниже 0) → defense; Ward поглощает урон предмета целиком.
- Руны 25/20/15/10/5: пробитие руны = +1 добор противнику (лечение руны не возвращает). Добор из пустой колоды или с 50-го хода игрока: за **каждую** недобранную карту минус руна, HP = её значение, без бонусного добора; проверка колоды идёт раньше проверки полной руки.
- Время: 1000 мс на первый ход драфта и первый ход боя, 100 мс на остальные. Ответ — одна строка, действия через `;`. Нелегальные действия — только warning; `PASS` внутри строки просто пропускается; синтаксически кривое действие (в т.ч. двойной пробел) = поражение.
- Ввод: 2 строки игроков (`hp mana deck rune draw`), `oppHand oppActions`, строки действий противника, `cardCount`, карты (`number instanceId location type cost atk def abilities myHp oppHp draw`). `mana` = maxMana; `draw` у меня — сколько добрал в этот ход, у противника — сколько доберёт в следующий. instanceId нечётные у первого игрока, чётные у второго (`GameState.IsSecondPlayer`).
- Причуда арбитра: у существа на столе поля myHp/oppHp/draw во вводе обнуляются после первого боя или предмета; зелёный предмет «не убивает» (существо остаётся как было).

## План этапов
0. ✅ Каркас: парсер, модель, заглушки, тесты, склейка.
1. ✅ Симулятор правил (`GameState`, применение действий, генерация легальных ходов) + тесты граничных случаев; сверка с движком арбитра: 62 случайные партии (~4000 ходов) и **1474 реальные партии Legend с арены (35 781 ход)** — 0 расхождений. В репозитории фикстуры: 24 случайных лога + 4 лога арены.
2. ✅ Драфт по рейтингу + мана-кривая; бой — полный перебор своего хода с простой оценкой. Локально: против random 10:0, self-play без таймаутов (полный перебор укладывается в ~35 мс, бюджет 85 мс), 0 нелегальных действий. На арене: Silver (формульный драфт, без модели ответа); с таблицей Legend и моделью ответа — Legend, 37-е место из 167 (56% побед по 230 партиям); со слабой кривой и глубоким ответом — **20-е место** (66% по 174 партиям; худшие соперники LH 1:6, Coac 1:4, dbdr 3:6).
3. Модель ответа противника ✅ (жадные атаки; self-play против версии без неё 19:11). Рейтинг драфта по пикам Legend ✅ (`CardTable`, 71 010 пиков из 1474 партий; self-play против формульного драфта 25:5). Сравнение с реальными ходами Legend (`compare`, 4000 ходов): совпадение 52.8%, поиск не пропускает ходы (0.1%), расхождения — в оценке (31%); веса hp/def/hand/reply дают ±0.5% (шум); с глубоким ответом `hp=0.3` даёт 55.4% (принят), штрафы за защиту 1–2 (`fragile1/2`) и бонус синим в руке (`blue`) снижают совпадение — выключены (веса оставлены для опытов). Обучение весов логистической регрессией на исходах партий (`tools/arena/learn_eval.py`, 15.8k позиций, точность 69%) даёт Ward/Lethal ×3, руку 2.3, но совпадение с ходами падает до 51.5%, self-play нейтрален — не принято; по весам оценка исчерпана, дальше только структурные изменения. Третий полуход (`CounterCandidates`: мой следующий ход после ответа противника, статика на листьях): совпадение 55.4% → 47.4%, до 94 мс — выключен (эффект горизонта); если возвращаться — только с ответом противника и на мой следующий ход. Отдельная оценка для модели противника (`SearchBattle.OppEval`, ключи `o_*`, режим `replycheck`: предсказанные атаки против реальных ответов Legend, база 46% целиком / 54% по существам): `o_oppdraw=0.5` предсказывает лучше (48.7/56.4%), но совпадение моих ходов 55.0% и self-play 8:22 — не принято; остальные `o_*` веса ничего не меняют. Расширение глубокой переоценки (deep=64, nodes=800) — без изменений. Примеры расхождений: Legend-боты дороже ценят карты в руке (не тратят removal ради мелкой выгоды) и добор. Разбор своих Legend-проигрышей (`fetch.py --handle`, `compare`, `draftcheck`): залитая версия играет как текущая (99.9%), леталов не пропускает; часть проигрышей — стартовые руки из одних 6+ карт (драфт без контроля кривой), исправлено слабой поправкой. Дальше: структурные изменения оценки (рука/добор, призыв противника в ответе), проверять через `compare` и self-play. Цель: верх Legend.
4. Локальный арбитр (Java/Maven) + self-play; тюнинг весов.

## Следующий шаг: партии с арены CodinGame (данные сильных ботов вместо self-play)
Нужен доступ к `www.codingame.com` (сетевая политика окружения: Network access = Custom, домены `www.codingame.com` и `*.codingame.com`; действует только для новых сессий). Затем `tools/arena/`: скрапер на Python без зависимостей.
Внутренний API (по чужим скраперам, проверить при первом запуске; все запросы — POST с JSON-массивом в теле):
- `https://www.codingame.com/services/Leaderboards/getFilteredPuzzleLeaderboard` тело `["legends-of-code-and-magic", null, "global", {"active": false, "column": "", "filter": ""}]` → игроки с `agentId` и лигой;
- `https://www.codingame.com/services/gamesPlayersRanking/findLastBattlesByAgentId` тело `[agentId, null]` → последние бои (`gameId`, игроки);
- `https://www.codingame.com/services/gameResult/findByGameId` тело `[gameId, null]` → кадры: `gameInformation` (тексты арбитра: «Player X chose …» на драфте, «performed action: …» в бою, «[Warning] … not legal»), `view` (данные просмотрщика с картами).
Цели: (1) таблица по картам — частота пика и винрейт колод с картой по лигам → рейтинг драфта D3 вместо формулы; (2) сравнение реальных ходов противников с `SearchBattle.ReplyScore`; (3) логи для `replay`.
