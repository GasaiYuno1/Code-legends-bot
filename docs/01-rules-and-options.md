# LOCM (Legends of Code & Magic) — правила и варианты реализации бота

Источник правил: официальный референс-репозиторий CodinGame (`CodinGame/LegendsOfCodeAndMagic`, Java) — константы и логика взяты прямо из кода движка, а не из пересказов.

> ⚠️ На CodinGame есть **две** игры: классическая *Legends of Code & Magic* (драфт, контест 2018) и *LOCM (Constructed)* (версия 1.5: фаза «констрактед» вместо драфта, две линии, area-эффекты). Этот документ — про **классическую**. Если цель — Constructed, часть правил и весь блок про драфт меняются.

---

## 1. Правила (кратко, но полно)

### 1.1 Общая схема
- 2 игрока, ничьих нет. Цель — опустить здоровье противника до 0.
- Партия = **драфт (30 ходов)** + **бой (до 50 ходов на игрока)**.
- Старт: 30 HP, колода 30 карт, стартовая рука 4 карты, рука ≤ 8, на столе ≤ 6 существ.
- Мана: +1 в ход, максимум 12. Второй игрок в компенсацию получает 5 стартовых карт вместо 4 и **+1 к максимуму маны до тех пор, пока впервые не потратит всю ману за ход** (после этого бонус исчезает).
- Карт всего 160: 116 существ, 24 зелёных, 12 красных, 8 синих предметов (`referee/cardlist.txt`).

### 1.2 Драфт
- Движок выбирает 60 карт из разрешённого пула, затем 30 раз показывает тройку разных карт из этих 60. Обоим игрокам показывают **одинаковые** тройки; каждый тайно берёт одну (можно взять одну и ту же).
- Ответ: `PICK <0|1|2>` (в референсе ещё принимается `PASS` = взять первую).
- После драфта колода перемешивается, каждой карте назначается уникальный `instanceId`.

### 1.3 Бой — ход игрока
1. Мана восстанавливается до максимума (+1, если < 12).
2. Добор: обычно 1 карта, плюс бонусы (руны, эффекты `cardDraw`). Если рука полна — лишние карты сгорают (остаются в колоде), следующий добор снова 1.
3. Игрок делает любое число действий одной строкой через `;`:
   - `SUMMON id` — выставить существо (стоимость маны; атаковать в тот же ход может только с **Charge**).
   - `ATTACK id targetId` — атака существом по существу противника или в лицо (`targetId = -1`). Маны не тратит, обычно 1 атака за ход на существо.
   - `USE id targetId` — сыграть предмет. Зелёный — только по своим существам; красный — только по чужим; синий — по чужим существам **или** в лицо противника (`-1`).
   - `PASS` — ничего.
   - Синтаксически корректное, но нелегальное действие даёт только warning и пропускается (движок продолжает с первого легального). Это удобно: не нужно бояться «сломать» ход.

### 1.4 Разрешение атак (точно по движку)
- Атакующий наносит `attack` в `defense` защитника, защитник одновременно наносит свой `attack` атакующему. Существо с `defense ≤ 0` умирает.
- **Guard** — пока у противника есть Guard-существа, атаковать можно только их.
- **Ward** — блокирует первый входящий урон (если он > 0) и снимается. Атака с 0 урона Ward не снимает.
- **Lethal** — любое существо, получившее > 0 урона от Lethal, умирает (Ward защищает).
- **Breakthrough** — если защитник убит, излишек урона идёт игроку (только на ходе атакующего; против Ward излишка нет).
- **Drain** — при нанесении > 0 урона на своём ходу атакующий игрок лечится на `attack` существа.
- **Charge** — атака в ход выставления. Если Charge дан предметом — атаковать можно только если существо выставлено в этот же ход и ещё не атаковало.
- Предметы: сначала меняют ключевые слова (зелёный добавляет, красный/синий снимают), потом attack/defense. Красный/синий предмет с отрицательным «defense» — это урон; синий в лицо добавляет `attack` (обычно отрицательный) к HP противника.
- Каждая карта дополнительно может менять `myHealthChange`, `opponentHealthChange`, `cardDraw` при розыгрыше.

### 1.5 Руны и пустая колода
- Руны на 25/20/15/10/5 HP. Когда HP игрока **впервые** опускается до/ниже руны — на следующий ход он добирает +1 карту за каждую пробитую руну (пример: 30→18 за ход = +2 карты).
- Добор из пустой колоды: игрок теряет следующую руну и его HP **ставится равным** её значению (если рун нет — HP = 0, проигрыш). То же на 50-м ходу игрока (`PLAYER_TURNLIMIT`).
- Практическое следствие (важно для оценки позиции): бить в лицо «чуть-чуть», пробивая руну, — плохо: даёшь противнику карту. Топ-боты учитывают это явно.

### 1.6 Формат ввода (каждый ход, и в драфте, и в бою)
```
playerHealth playerMana playerDeck playerRune playerDraw     # я
playerHealth playerMana playerDeck playerRune playerDraw     # противник
opponentHand opponentActions
<opponentActions строк: "cardNumber action">                # что противник делал в свой ход
cardCount
<cardCount строк:>
cardNumber instanceId location cardType cost attack defense abilities myHealthChange opponentHealthChange cardDraw
```
- `location`: 0 — моя рука, 1 — мой стол, −1 — стол противника. Руку противника не видим (только количество).
- `cardType`: 0 существо, 1 зелёный, 2 красный, 3 синий предмет.
- `abilities`: 6 символов `BCDGLW` или `-`.
- В драфте: мана 0, `cardCount = 3`, location 0.

### 1.7 Лиги и лимиты
| Лига | Пул карт |
|---|---|
| Wood 3 | только существа без способностей и без эффектов |
| Wood 2 | только существа, без Drain/Lethal/Ward |
| Wood 1 | + предметы, всё ещё без Drain/Lethal/Ward |
| Bronze и выше | все 160 карт |

- Время: **1000 мс** на первый ход драфта и первый ход боя, **100 мс** на каждый остальной ход (и драфта, и боя).
- Ответ выводится **одной строкой** за ход.

## 2. Что известно о сильных решениях (контест 2018, Legend)

Общие выводы из постмортемов топ-игроков:
1. **Драфт решает больше, чем бой.** Почти вся легенда играла захардкоженным рейтингом карт (списком ClosetAI — победителя контеста); сильные боты сверху корректировали рейтинг под мана-кривую уже набранной колоды.
2. **Бой:** полный перебор своего хода (summon → предметы → атаки) с симулятором + оценка позиции. Глубина «2 полухода» (мой ход + приблизительный ответ противника) работает лучше, чем глубже: за 100 мс дерево атак взрывается комбинаторно.
3. **Простая оценка выигрывает у сложной.** Сумма `attack + defense` существ на столе с бонусами за Guard/Lethal/Ward и штрафом за здоровье — это уровень топ-30. Усложнение чаще ухудшало результат.
4. **Отсечения важнее глубины:** фиксированный порядок атак (существа с меньшей атакой первыми, снятие Ward дешёвым существом, сначала Guard-фаза), хеширование состояний, битовые представления — дают ×20 к числу симуляций.
5. **Учёт рун** в оценке (не пробивать руну «даром», добивать в один ход) — отличительный признак топ-10.
6. Нейросети/RL (DaFish, 45-е) и полноценный MCTS (Magus, 70-е) не окупились в рамках 100 мс.

## 3. Варианты реализации

### 3.1 Фаза боя

| # | Подход | Суть | Плюсы | Минусы | Ожидаемый потолок |
|---|---|---|---|---|---|
| A | **Эвристический бот** | Жёсткие правила: играть карты по мане с наибольшим рейтингом, атаковать по приоритетам (убрать Guard → выгодные размены → лицо) | 1–2 дня, без симулятора | Не видит комбинаций (предмет + атака, порядок атак), быстро упирается | Silver / нижний Gold |
| B | **Симулятор + полный перебор своего хода** (путь ClosetAI/MSmits) | Своя копия движка; DFS по всем последовательностям действий с отсечениями (упорядочивание, дедупликация состояний по хешу); в листьях — эвристическая оценка; опционально грубая модель ответа противника | Проверенный путь в топ; детерминированно, легко отлаживать; симулятор переиспользуется для тюнинга драфта | Нужна точная копия правил (сверка с референсом); работа над отсечениями | Legend, топ-10 при хорошей оценке и драфте |
| C | **Симулятор + Monte-Carlo (случайные раскаты)** | Много случайных последовательностей за 100 мс, выбор лучшей по оценке; варианты — beam search / случайный поиск с мутациями | Проще перебора, устойчиво к взрыву дерева | Хуже находит точные лethal-комбинации; шумит | Legend (средняя часть) |
| D | **MCTS / ISMCTS** | Дерево с UCT, неизвестная рука противника рандомизируется | Универсально | За 100 мс дерево мелкое, выигрыша над B нет, сложнее | Gold / нижний Legend |
| E | **NN / RL** | Обучение оценочной функции или политики self-play | Интересно | Долго, дорого, в контесте проиграло ручным подходам | неясно |

**Рекомендация: B**, с возможностью добавить элементы C (случайные раскаты) для сложных позиций, где перебор не влезает в 100 мс.

### 3.2 Оценка позиции (для B/C)
Стартовать с простого линейного скора и настраивать по результатам self-play:
`Σ моих существ (attack·wa + defense·wd + бонусы способностей) − то же для противника + f(myHP) − f(oppHP) + учёт карт в руке и рун`,
где `f(HP)` — кусочно-линейная (дорожить HP при малых значениях, не пробивать руны противника). Веса — сначала руками по постмортемам, потом автоматическим тюнингом (self-play локально).

### 3.3 Драфт

| # | Подход | Плюсы | Минусы |
|---|---|---|---|
| D1 | **Статический рейтинг** 160 карт (свой + известные списки Legend-игроков) | Быстро, сразу сильный | Не учитывает состав колоды |
| D2 | D1 + **коррекция под мана-кривую** и состав (кол-во Guard, removal, количество предметов) | Заметный плюс к D1, дёшево | Нужны параметры (целевая кривая) |
| D3 | **Статистический рейтинг** из self-play: «винрейт при вытягивании карты» на тысячах локальных игр | Объективно, подстраивается под наш бой | Требует локального арбитра и быстрого бота; рейтинг смещён к нашему стилю игры |
| D4 | **Оптимизация весов** (GA / случайный поиск) на локальных матчах | Может дать лучший результат | Самый дорогой по времени |

**Рекомендация:** D1 → D2 сразу, D3 когда появится локальный self-play.

### 3.4 Язык
- **C#** — знаком, на CodinGame доступен; для перебора с отсечениями скорости хватает, если избегать аллокаций (struct-состояния, массивы, без LINQ в горячем пути).
- **C++** — максимум симуляций за 100 мс; имеет смысл, только если упрёмся в производительность.
- Схема как в предыдущем проекте: **начинаем на C#**, порт горячего ядра — только при доказанной необходимости.

### 3.5 Инфраструктура (нужна при любом варианте ≥ B)
- Локальный **референс-арбитр** (официальный Java-проект собирается через Maven → jar) для запуска матчей бот-против-бота и точной сверки симулятора.
- **Сверка симулятора:** прогон логов реальных игр через наш симулятор и сравнение состояния с тем, что присылает арбитр на следующем ходу (любое расхождение = баг правил).
- **Сборка одного файла** для CodinGame (склейка исходников в один `.cs`).
- Тесты на ключевые кейсы правил (Ward+Lethal, Breakthrough против Ward, Charge через предмет, руны, переполнение руки).
